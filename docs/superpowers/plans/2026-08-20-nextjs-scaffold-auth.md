# Next.js Scaffold with Role-Based Auth — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold a real Next.js application (living alongside the existing HTML prototype) with two role-protected areas — `/survey` (employees) and `/admin` (HR) — a minimal backend API route, and a CI pipeline, so the team can connect it to Vercel and see a working deploy.

**Architecture:** Single Next.js (App Router, TypeScript) app in `web/`. Frontend pages and backend API routes live in the same deployable, per `docs/architettura-proposta-pilota.md`. Route access is gated by Next.js middleware that reads the authenticated user's role from Supabase Auth (`app_metadata.role`, set server-side, not user-editable). Route-matching/role-checking logic is implemented as small pure functions so it can be unit-tested without a live Supabase project; the thin Supabase-specific glue (client creation, session lookup) is verified manually.

**Tech Stack:** Next.js (App Router, TypeScript), `@supabase/ssr` + `@supabase/supabase-js`, Vitest for unit tests, GitHub Actions for CI, npm.

## Global Constraints

- The existing prototype `Open_Listening_Active_Care_Prototype.html` at the repo root is NOT modified or removed by this plan — it stays as UX/UI reference until its content is ported into `/survey` in a later plan.
- The new app lives entirely under `web/` — nothing at the repo root is touched except adding `.github/workflows/ci.yml` and this plan/doc.
- Language: all user-facing copy (page text, error messages shown to users) is in Italian, colloquial tone, consistent with `CLAUDE.md`'s stated preference. Code, comments, commit messages, and this plan are in the style already used in this repo (commit messages in Italian, per prior commits).
- Package manager: npm (no yarn/pnpm lockfiles).
- Two roles only for now: `employee` and `hr_admin` — matches `docs/architettura-proposta-pilota.md` section 4.
- Auth mechanism: Supabase Auth email/password (NOT Google OAuth) — per the pilot decision in `docs/architettura-proposta-pilota.md` section 5.

## Out of scope (follow-up plans, not this one)

- Porting the actual survey UI/logic from the HTML prototype into `/survey`.
- Building the real HR dashboard metrics/queries into `/admin` (metrics are still functionally undefined, per the architecture doc).
- Supabase database schema, migrations, and RLS policies (`users`, `nominative_responses`, `anonymous_tokens`, `anonymous_responses` from the architecture doc's data model) — and therefore no Supabase CD/migration pipeline yet. That needs its own plan once the schema is designed.
- Actually creating and provisioning real employee/HR accounts (invite flow) — needs the schema above first.
- Connecting the Vercel GitHub integration itself is a manual dashboard action (documented in Task 8), not something scriptable from this repo.

- [ ] **Step 6: Implement `web/src/lib/auth/routeAccess.ts`**

```typescript
export type Role = 'employee' | 'hr_admin'

interface RouteRule {
  pathPrefix: string
  allowedRoles: Role[]
}

const PROTECTED_ROUTES: RouteRule[] = [
  { pathPrefix: '/survey', allowedRoles: ['employee', 'hr_admin'] },
  { pathPrefix: '/admin', allowedRoles: ['hr_admin'] },
]

export function getRequiredRoles(pathname: string): Role[] | null {
  const rule = PROTECTED_ROUTES.find((r) => pathname.startsWith(r.pathPrefix))
  return rule ? rule.allowedRoles : null
}

export function isRoleAllowed(pathname: string, role: Role | null): boolean {
  const required = getRequiredRoles(pathname)
  if (!required) return true
  if (!role) return false
  return required.includes(role)
}
```

```typescript
export async function createClient() {

  const { url, anonKey } = getSupabaseEnv()
```

- [ ] **Step 1: Implement `web/src/middleware.ts`**

```typescript
import { NextResponse, type NextRequest } from 'next/server'
import { createServerClient } from '@supabase/ssr'
import { getSupabaseEnv } from '@/lib/supabase/env'
import { getRequiredRoles, isRoleAllowed, type Role } from '@/lib/auth/routeAccess'

export async function middleware(request: NextRequest) {
  const response = NextResponse.next({ request })
  const requiredRoles = getRequiredRoles(request.nextUrl.pathname)

  if (!requiredRoles) {
    return response
  }

  const { url, anonKey } = getSupabaseEnv()
  const supabase = createServerClient(url, anonKey, {
    cookies: {
      getAll() {
        return request.cookies.getAll()
      },
      setAll(cookiesToSet) {
        cookiesToSet.forEach(({ name, value }) => request.cookies.set(name, value))
        cookiesToSet.forEach(({ name, value, options }) =>
          response.cookies.set(name, value, options)
        )
      },
    },
  })

  const {
    data: { user },
  } = await supabase.auth.getUser()

  const role = (user?.app_metadata?.role as Role | undefined) ?? null

  if (!isRoleAllowed(request.nextUrl.pathname, role)) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  return response
}

export const config = {
  matcher: ['/survey/:path*', '/admin/:path*'],
}
```

- [ ] **Step 2: Implement `web/src/app/login/page.tsx`**

```tsx
'use client'

import { useState, type FormEvent } from 'react'
import { useRouter } from 'next/navigation'
import { createClient } from '@/lib/supabase/client'

export default function LoginPage() {
  const router = useRouter()
  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')
  const [error, setError] = useState<string | null>(null)

  async function handleSubmit(event: FormEvent) {
    event.preventDefault()
    setError(null)

    const supabase = createClient()
    const { error: signInError } = await supabase.auth.signInWithPassword({
      email,
      password,
    })

    if (signInError) {
      setError('Email o password non corrette.')
      return
    }

    router.push('/survey')
    router.refresh()
  }

  return (
    <main>
      <h1>Accedi</h1>
      <form onSubmit={handleSubmit}>
        <label>
          Email
          <input
            type="email"
            value={email}
            onChange={(e) => setEmail(e.target.value)}
            required
          />
        </label>
        <label>
          Password
          <input
            type="password"
            value={password}
            onChange={(e) => setPassword(e.target.value)}
            required
          />
        </label>
        {error && <p role="alert">{error}</p>}
        <button type="submit">Accedi</button>
      </form>
    </main>
  )
}
```
